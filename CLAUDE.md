# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Roya House ERP is a sales and warehouse app for a drywall / suspended-ceiling supplier. There's an Express + PostgreSQL backend and a React + Vite + shadcn/ui frontend. The UI is **Persian (Farsi), RTL**. It produces three document types that copy the company's paper forms: Proforma (پیش فاکتور), Invoice (فاکتور), and Goods Issue (حواله خروج از انبار). Each one can be exported to PDF.

The repo is on GitHub at `siamand-shirzad/roya-house-erp` (public, branch `main`). There are no tests.

## Commands

Backend (`backend/`, runs on http://localhost:4000):
```bash
docker compose up -d        # from repo root: optional local Postgres 16 (postgres:postgres@localhost:5432/royahouse)
npm run prisma:seed         # creates tables (SCHEMA_SQL) + upserts the price list and sample docs; same as `npm run db:setup`
npm run dev                 # tsx watch src/index.ts (also runs SCHEMA_SQL on startup, so new tables appear automatically)
npm run build               # tsc -> dist/
npm run hash-password       # locked-out admin: prompts for username + new password, writes reset-password.sql (gitignored) to run on the production DB
npm run hash-password -- --apply   # same, but writes straight to the database in DATABASE_URL (use it in the Liara console)
```
Health check: `GET /api/health`. `backend/.env` needs `DATABASE_URL`, and optionally `PORT` and `CORS_ORIGIN` (comma-separated, default `http://localhost:5173`).

Frontend (`frontend/`, runs on http://localhost:5173):
```bash
npm run dev
npm run build               # tsc -b && vite build (this is the type check)
```
`VITE_API_URL` defaults to `http://localhost:4000/api`. There's a `lint` script, but the project has no ESLint config, so it won't run as-is.

On this Windows machine, Docker Desktop has to be running before `docker compose up -d`. `.claude/launch.json` defines `backend` and `frontend` preview configs.

`@tanstack/react-table` (v8) is used by `components/customers/CustomerDataTable.tsx`. Import types from `@tanstack/react-table` itself, not guessed names: column visibility state is `VisibilityState`, not `ColumnVisibilityState`. If a new table is added elsewhere, use the same v8 API (`useReactTable`, `getCoreRowModel`, ...) — v9 dropped it. `vite.config.ts` sets an inline `css.postcss: {}` so Vite doesn't search parent folders for a PostCSS config (a stray empty `C:\Users\ASUS\package.json` broke that search). Tailwind v4 runs through `@tailwindcss/vite`.

## Deployment

The repo root has a `package.json` whose only job is deployment: `build` installs and builds `backend/` and `frontend/`, `start` runs `node backend/dist/index.js`. In production the Express server **also serves `frontend/dist`** (static files plus an index.html fallback for client-side routes), so the API and the SPA share one origin: no CORS, and the `SameSite=Lax` session cookie keeps working. `frontend/.env.production` bakes `VITE_API_URL=/api` into the bundle at build time. `liara.json` targets the `node` platform on port 3000, because Liara injects `PORT=3000` into the container regardless of `liara.json` and routes to the `liara.json` port, so the two must match (a 4000 there gave 502s); `DEPLOY.md` has the full checklist. `backend/src/lib/env.ts` loads `backend/.env` by absolute path, because `npm start` runs from the repo root where a plain `dotenv/config` would find nothing. `app.set("trust proxy")` is on when `NODE_ENV=production`, so the login throttle sees real client IPs behind the platform proxy.

`backend/tsconfig.json` must emit **CommonJS** (`"module": "commonjs"`), matching `"type": "commonjs"` in `backend/package.json`. It used to say `"module": "preserve"`, which left ESM `import` syntax in `dist/` that node refused to load — only `tsx` (dev) ever ran it.

## Docs don't match the code

- **The backend uses raw SQL over `pg`, not Prisma.** All data access goes through `backend/src/lib/db.ts` (`pool`, `query`, `queryOne`, `newId`). Prisma's engine binaries couldn't be downloaded in the original build environment, so Prisma was dropped.
- `backend/prisma/schema.prisma` is only kept as a readable model reference. The real schema is the `SCHEMA_SQL` string in `db.ts`, which uses snake_case tables and columns.
- The Prisma packages (`prisma`, `@prisma/client`, `@prisma/orm-postgres`, `@prisma/cli-engine`) and the unused Prisma Next scaffold (`backend/src/prisma/`, `prisma.config.ts`, `prisma-next.md`) were removed: nothing imported them, and they put about 1 GB into every install and into the Liara image. `backend/README.md` is still an out-of-date Prisma readme. `npm run prisma:seed` keeps its old name but only runs `tsx prisma/seed.ts`.
- The root README and `frontend/setup.sh` mention `npm run prisma:migrate` and `prisma:studio`. Neither script exists. There are no migrations: `SCHEMA_SQL` only uses `CREATE TABLE IF NOT EXISTS`. That means changing a column on an existing table needs a manual `ALTER TABLE`, plus a matching update to `SCHEMA_SQL`.
- `frontend/src/components/ui/*` and the dashboard-01 components (`app-sidebar`, `site-header`, `section-cards`, `chart-area-interactive`) are already in the repo, but there's no `components.json`. Running `setup.sh` / `shadcn add` may overwrite them.

## Architecture

**Backend** (`backend/src/`): `index.ts` mounts the routers under `/api` (`auth`, `public`, `products`, `customers`, `documents`, `users`, `reports`, `company`, `inventory`). `withTransaction` and `pgErrorCode` live in `lib/db.ts`. The central error handler turns a `ZodError` into a 400 response and passes other 4xx errors through (e.g. malformed JSON), so routes `parse()` with zod and pass errors to `next(err)`.
- `PATCH /api/products/bulk` saves many price edits in one transaction (an unknown id rolls the batch back). `POST /api/products/import` upserts CSV rows by `code`, and never deletes or deactivates products that are missing from the file.
- **Auth** (`lib/auth.ts`, `routes/auth.ts`): scrypt password hashes and cookie sessions (`rh_session`, HttpOnly, SameSite=Lax; only the SHA-256 of the token is stored in `sessions`). `authenticate` runs on every request. `/api/health`, `/api/auth/*` and `/api/public/*` are public, and everything else goes through `requireAuth`. Only `ADMIN` can write products or use `/api/users`. On first run (no active admin with a password), `POST /api/auth/setup` creates the first admin. Logins are throttled in memory (10 failures per username+IP per 15 min). CORS uses `credentials: true`, and the frontend sends `credentials: "include"`.
- `users`: name, username, phone, role `ADMIN|SALES|WAREHOUSE|ACCOUNTANT`, active, `password_hash`, `last_login_at`. The API refuses to demote or deactivate the last active admin. Deactivating a user or resetting their password deletes their sessions. Unique-violation errors (`23505`) map to 409.
- `/api/public/catalog` only returns category counts for the landing page. Never expose prices from public routes.
- Routes convert snake_case DB rows to camelCase JSON by hand (`rowToCompany`, `rowToItem`, and similar in `routes/documents.ts`). A new column has to be added in `SCHEMA_SQL`, in the INSERT/UPDATE statements, in the row mapper, and in the zod schema.
- IDs are prefixed text UUIDs from `newId("doc" | "item" | "prod" | ...)`.
- Document numbers are assigned per type as `max(number)+1`, starting from `STARTING_NUMBER` (so numbering continues from the real paper documents). `(type, number)` is unique.
- Creating or updating a document runs in a transaction. On update, the item list is replaced completely: all items are deleted and reinserted with `row_no` values.
- **Document lifecycle**: `DRAFT -> ISSUED -> CANCELLED`. Only drafts can be edited or deleted; issuing (`POST /:id/issue`) locks the document and stamps `issued_at`/`issued_by`. Issued documents are never deleted, only cancelled (`POST /:id/cancel`, optional `reason`) — cancelling is blocked while a non-cancelled document was converted from it (`source_document_id`). Document numbers are assigned inside an advisory-locked transaction (`pg_advisory_xact_lock` keyed by type) so concurrent creates can't collide.
- **Conversion** (`POST /:id/convert {to}`): copies an *issued* document's items and buyer into a new draft of the next type (`PROFORMA -> INVOICE -> GOODS_ISSUE`, see `NEXT_TYPE`/`NEXT_DOCUMENT_TYPE`), linked via `source_document_id`. A goods issue's `relatedInvoiceNo` is filled in automatically from the source invoice's number. Converting twice returns the existing draft/issued document instead of creating a duplicate.
- **Per-type write roles** (`WRITE_ROLES` in `routes/documents.ts`, mirrored in the frontend as `DOCUMENT_WRITE_ROLES` in `types.ts` — the frontend copy only hides buttons, the backend is the real check): PROFORMA/INVOICE need `ADMIN`or `SALES`; GOODS_ISSUE needs `ADMIN` or `WAREHOUSE`. Reading any document just needs to be signed in.
- `GET /api/documents` (optional `type`, `customerId`) loads documents in batches (`loadDocuments(ids)`: a fixed number of `= ANY($1)` queries, not five per document); `loadDocument(id)` is the one-id case. Keep the JSON shape identical when adding fields.
- Deleting a product is a soft delete (`active = false`). Deleting a customer (`ADMIN`/`SALES`) is a hard delete and is refused with 409 `Customer has documents` while any document points at it.
- **Company** (`routes/company.ts`): the single seller row printed on documents. `GET /api/company` for everyone signed in, `PUT` for `ADMIN` (page `/settings/company`). `ensureCompany()` runs at startup and inserts the default `royahouse-main` row when the table is empty, so an unseeded production database still has a seller. New documents link to `currentCompany()` (oldest row).
- `POST /api/auth/password {currentPassword, newPassword}`: users change their own password (throttled like login; a wrong current password is a 400, not a 401, so it never signs the user out). Other sessions are deleted, the current one stays. UI: "تغییر رمز عبور" in `NavUser`.
- **Inventory** (`routes/inventory.ts`, page `/inventory`): stock on hand is `sum(stock_movements.quantity)` per product and is never stored. Movement kinds: `RECEIPT` (+, `POST /receipts`), `ADJUSTMENT` (± difference between a count and the booked stock, `POST /adjustments`; also how opening stock is entered), `ISSUE` (−, written when a goods issue is issued) and `ISSUE_REVERSAL` (+, written when it is cancelled, mirroring exactly the `ISSUE` rows that document booked, so goods issues issued before inventory existed reverse nothing). Issue/cancel re-check the status under `SELECT ... FOR UPDATE` in the same transaction as the movements. Short stock **warns but never blocks**: stock may go negative; `/issue` returns `stockWarnings`, and the form asks first (`shortfallsFor` in `DocumentFormPage`). Rows without a `product_id` (typed by hand) are not tracked. `products.min_stock` (`PATCH /min-stock`) drives "low" (`lib/stock.ts` `stockLevel`: negative, or below a set minimum; no minimum = never low). Reads are open to all signed-in roles; writes need `ADMIN`/`WAREHOUSE` (`INVENTORY_WRITE_ROLES`, mirrored in `types.ts`). The dashboard's fourth card counts low-stock products.
- Buyer details are **copied onto the document** (`buyer_*` columns) as well as the optional `customer_id`. Printed documents keep the buyer data from when they were created.

**Totals**: `computeLineTotals` / `computeDocumentTotals` exist twice, in `backend/src/lib/totals.ts` (server, authoritative, recomputed on every load and save) and `frontend/src/lib/totals.ts` (live preview). **Keep them identical.** The formula per line: `lineTotal = round(qty*unitPrice)`, subtract `discount` (an absolute amount), then add `round(afterDiscount*taxRate/100)`.

**Money**: prices are stored as integers in **Toman**. The printed documents show **Rial**, which is Toman × 10 (`formatRial` in `frontend/src/lib/format.ts`). Quantities are `numeric(12,2)`, and `pg` returns them as strings, so they're wrapped in `Number()`.

**Theming / layout**: every page renders inside `AppShell` (`components/app-shell.tsx`), which provides the right-side inset sidebar and a sticky `SiteHeader` (title, per-page actions, theme toggle). Dark mode is the `.dark` class on `<html>`, managed by `ThemeProvider` (`light`/`dark`/`system`, saved in localStorage key `roya-theme`). An inline script in `index.html` applies it before first paint, so keep the key in sync in both places. Use theme tokens (`bg-card`, `text-muted-foreground`, `bg-primary/10`, ...) rather than fixed colors, **except in `DocumentPrint`**: it is paper and deliberately stays white with fixed `neutral-*` colors in both themes. `DocumentPrint` (paper/PDF) uses fixed brand hex colours: grey section headers with a red start bar, a red header rule and title, a light red totals row, and a charcoal footer band. It is tuned so a **17-line invoice still fits one A4 page** (a 10-line one measures 980px against A4's 1123px at the sheet's fixed 794px width): the seller/buyer boxes are a 4-column grid at `text-[10.5px]` (three short rows, not five), and the items table is `table-fixed` at `text-[10px]` with the money columns given explicit widths. Two things keep it that way — the money columns are sized for the **totals row**, which holds the sum of every line and so is always the widest number in its column, and the currency is stated once as a note in the section header instead of "(ریال)" in all six headings, which would wrap the headings and squeeze the product-name column until the names wrapped too. If you add a column, re-check both: overflow shows up as figures colliding in the totals row. The app theme is **grey neutrals plus one mellow red**: surfaces, text and borders in `index.css` are neutral greys (chroma 0), and the accent is the logo's red with its chroma turned down (`--primary` ≈ `oklch(0.5 0.105 22)` light / `oklch(0.7 0.1 22)` dark). The red marks the primary action, focus rings, the active sidebar icon, `bg-primary/10` icon chips and `--chart-1` (single-series charts); `--chart-2`…`--chart-5` are greys. `--destructive` stays hotter and more saturated so it never reads as the accent, and destructive actions still carry an icon and wording. Status badges keep their semantic green/red/amber, and `DocumentPrint` keeps the exact brand red because it reproduces the paper forms. The sidebar used to be charcoal in both themes; it's now part of the same paper-like surface system in light mode (`--sidebar` ≈ the page background, a hair darker) and stays a dark charcoal only in `.dark`, so `LogoMark` picks its light/dark variant with `dark:hidden`/`dark:block` instead of always rendering `onDark`.

**Motion**: soft, ease-out, and always behind `motion-safe:` / `prefers-reduced-motion`. Shared pieces live in `lib/motion.ts`: `REVEAL` (fade + rise entrance classes) with `stagger(i)` for cards that arrive one after another, and `useCountUp`, used through `components/animated-number.tsx` so headline figures count up (screen readers get the final value only). Page content also fades in on the `AppShell` wrapper; `components/segmented-control.tsx` slides one selection pill between options (document type tabs, report ranges, the status filter); buttons press to `scale-[0.98]`; dashboard cards lift and their icon chips grow on hover; the theme toggle turns sun into moon; ranking bars grow with the `animate-bar-grow` utility in `index.css`; and body colours cross-fade when the theme changes.

**Logo**: `components/brand-logo.tsx` (`surface="auto" | "light" | "dark"`). The files in `frontend/public/brand/` are transparent PNGs generated from `roya-house-logo-original.jpg`, which has a black background: `roya-house-logo.png` is for light surfaces, and `-on-dark.png` has lifted greys for dark ones. The sidebar uses `LogoMark` (the logo's tile grid as SVG), rendering the light variant and the `onDark` variant side by side with `dark:hidden`/`dark:block` now that the sidebar itself switches surface with the theme; `DocumentPrint` (PDF) always uses `surface="light"`, and the login page and landing header use `auto`. Put `md:hidden`-style visibility classes on a wrapper, not on `BrandLogo`: on the `<img>` they lose to its `dark:block`. The favicon in `index.html` is the logo's tile grid as an inline SVG.

**Icons**: all icons are `lucide-react`. `frontend/src/lib/icons.tsx` is the single source of truth for the two things that get drawn in more than one place: `DOCUMENT_TYPE_ICONS` (PROFORMA = `FileClock`, INVOICE = `ReceiptText`, GOODS_ISSUE = `Truck`) and `CATEGORY_ICONS` (one per `ProductCategory`). Render them through the `DocumentTypeIcon` / `CategoryIcon` wrappers rather than picking an icon inline, so the sidebar, the dashboard cards, the list pages and the landing page never show the same thing two different ways. Both maps are exhaustive `Record`s, so a new document type or product category won't type-check until it has an icon. Import lucide's **canonical v1 names**, not the deprecated v0 aliases it still re-exports for back-compat (`LoaderCircle` not `Loader2`, `TriangleAlert` not `AlertTriangle`, `Trash` not `Trash2` — each alias resolves to the same component, so this is naming only). The `*Icon`-suffixed forms in `components/ui/*` are a separate shadcn convention and stay as they are.

**Price list page** (`/products`, `pages/ProductsPage.tsx`): a spreadsheet-style grid. Pack size is shown after the unit in parentheses (`برگ (90)`) rather than in its own column. `components/products/PriceCell.tsx` handles one editable price. Cells are addressed by `data-grid-row`/`data-grid-col`: Enter/↓ moves down, Shift+Enter/↑ moves up, Esc reverts, and Tab uses the native order. Edits are kept as drafts until "ذخیره", which calls the bulk endpoint. Rows sort by *saved* prices so they don't jump while being edited. CSV logic is in `lib/csv.ts` (parse/format, windows-1256 fallback, Persian digits via `parseAmount`) and `lib/priceListCsv.ts` (column aliases, and a diff preview against the current catalog). Export → import of unchanged data must produce zero changes.

**Public landing page** (`/site`, `pages/site/LandingPage.tsx`): renders outside `AppShell`. It follows the `design-taste-frontend` skill (`.claude/skills/`): the dials are noted at the top of the file, and hover motion uses the shared `EASE`/`LIFT`/`BUTTON_MOTION` classes with all movement behind `motion-safe:`. Copy must come from real business facts (price list, document terms), with no invented stats. Photos are loaded from `frontend/public/site/` (see the README there). `SitePhoto` shows a placeholder when a file is missing.

**Fonts and digits**: fonts are self-hosted via `@fontsource`/`@fontsource-variable` (imported in `main.tsx`), with stacks defined in `index.css` `@theme`. `font-sans` = Inter, `font-display` = Space Grotesk (h1-h3, `CardTitle`, sidebar group labels), `font-mono` = Geist Mono. An earlier attempt at drawing digits from IBM Plex Mono (for its marked zero, via a `unicode-range` `@font-face`) was tried and rejected; the current approach instead switches the whole element to `font-mono` (Geist Mono) wherever digits need a stable rhythm, via the `.tabular-nums` / `[data-numeric]` / `input[type="number"]` rule in `index.css` (`font-variant-numeric: tabular-nums slashed-zero`), rather than mixing glyphs from two fonts on one baseline. **Amounts always show a comma every three digits**: display goes through `formatToman`/`formatNumber`, and editable number fields use `components/number-input.tsx` (`NumberInput`), which groups while typing, keeps the caret on the same digit, accepts Persian digits and the Persian decimal separator, and hands back a plain number. Identifiers (document numbers, product codes) are never grouped (`toDisplayDigits`). Persian letters fall back to IBM Plex Sans Arabic. The UI and PDFs use **Latin digits**: `toDisplayDigits` in `lib/format.ts` has a single `USE_PERSIAN_DIGITS` switch. Input parsing still accepts Persian digits (`parseAmount`).

**Auth UI**: `AuthProvider`/`RequireAuth` are in `components/auth-provider.tsx`. `/login` shows setup mode on first run. `/site` and `/login` are public; every ERP route is wrapped in `RequireAuth`, and `/users` requires `roles={["ADMIN"]}`. A 401 from any API call fires `UNAUTHORIZED_EVENT` and returns to login. Non-admins see the price list read-only (`PriceCell readOnly`).

**Sidebar**: modelled on the shadcn `sidebar-07` block, merged by hand. Don't run `shadcn add sidebar-07`: it would overwrite the RTL-adjusted `ui/sidebar.tsx` and `app-sidebar.tsx`, and it writes a Next.js `app/dashboard/page.tsx`. It has `collapsible="icon"`, the open state is saved in localStorage (`roya-sidebar-open`), the brand is `LogoMark` + "Roya House", group labels are English, and `NavUser` (user, theme and logout menu) is in the footer. `components.json` exists now, and the root `tsconfig.json` has the `@/*` path so `shadcn add` writes into `src/`. New shadcn components use the `radix-ui` package and physical `left`/`right`/`pl` classes, so convert them to logical ones (`start`/`ps`/`ms`) for RTL. Two more things to fix after every `shadcn add`: the registry now writes `import { cn } from "cn"` (a real but unrelated npm package — it must be `@/lib/utils`), and the CLI silently rewrites `ui/button.tsx` even when you only asked for other components, which reverts the 20px icon sizing. Check `git diff` right after adding, and `git checkout -- ui/button.tsx` if it was touched.

**Command palette** (`components/command-menu.tsx`): `Ctrl+K` / `⌘K` or `/` opens it from any signed-in page (the sidebar has a `Search · Ctrl K` button under the brand too, drawn with the four-pane Windows glyph from `components/windows-icon.tsx` since lucide has no brand icons). It searches documents (number, buyer), products and commands, and the two-key shortcuts are `G D` dashboard, `G S` documents, `G P` products, `G C` customers, `G I` inventory, `G R` reports (admin/accountant), `G U` users (admin), `G O` company settings (admin), `N P` / `N I` / `N G` new proforma / invoice / goods issue (only for roles that can write that type). Keys match `KeyboardEvent.code`, the physical key, so shortcuts still work with a Persian layout active; they are ignored while typing in a field or while a dialog or menu is open. Filtering goes through `lib/search.ts` (`normalizeSearch`/`matchesSearch`: Persian digits, Arabic yeh/kaf, ZWNJ), not cmdk's own filter. `/products?q=` pre-fills the price-list search.

**Reports** (`/reports`, `pages/ReportsPage.tsx`; `ADMIN` and `ACCOUNTANT` only, via `REPORT_ROLES` in `types.ts` and `requireRole` on `/api/reports`): one endpoint, `GET /api/reports?from&to` in `backend/src/routes/reports.ts`, aggregates in SQL instead of loading documents. Only **ISSUED** documents count. Line amounts repeat the `lib/totals.ts` formula in SQL, and days are grouped and filtered in `Asia/Tehran`. It returns sales KPIs, daily totals (the page fills empty days with zero and buckets ranges over 62 days by Jalali month), top customers and products, sales by category, proforma→invoice conversion, and two follow-up lists that ignore the range: issued proformas with no non-cancelled invoice, and issued invoices with no goods issue (linked by `source_document_id` **or** a hand-typed `related_invoice_no`). Range presets are Jalali (`jalaliToGregorian` in `lib/format.ts`). Charts follow the dataviz skill: one grey series, one axis, tooltip plus a table view.

**Forms in modals**: add/edit forms (product, customer, user) and the CSV import preview open in `components/form-dialog.tsx` (`FormDialog`), not sheets. **Dialogs must not scroll**: they are sized to fit instead, with fields several per row in a 3–4 column grid, compact inputs, and one-line hints. Use the `FIELD` / `LABEL` / `INPUT` class constants exported next to `FormDialog`, plus `SelectTrigger size="sm"` and `size="sm"` footer buttons. Measured in a 1280×529 window: new product 337px, edit product 369px, new customer 401px, CSV preview in its fullest case (errors, new and changed rows) 467px. The CSV import preview shows counts plus the first rows of each list (5 new, 5 changed side by side, 2 errors) with "و N مورد دیگر" rather than a scrolling list. Only below the `sm` breakpoint (phones), where a form can't fit, do the dialog and its body fall back to scrolling. While `busy`, Esc and outside clicks can't close it. No page uses `Sheet` directly any more (the sidebar still does on mobile).

**Header and navigation**: the header shows a back button on every page except the dashboard. It goes back in history, or, when the page was opened directly (react-router's `history.state.idx` is 0), to the document's list or the dashboard. On the document form, the buyer card is a shadcn `Collapsible` that **starts closed** on every document, showing a one-line summary (name · phone · city) and expanding on demand, so the items table starts at the top; the buyer and delivery fields use compact small-label inputs, several per row. `Collapsible` is used with `asChild` so `Card` is the collapsible root, which means Radix's `data-slot="collapsible"` replaces `Card`'s own `data-slot="card"` on that element — nothing selects it, but don't add a `[data-slot=card]` rule expecting to catch it.

**Pagination**: the customers list pages on the client, 10 rows at a time, through `components/list-pagination.tsx` (`usePagination(rows, resetKey)` + `ListPagination`); the documents list pages on the **server** instead (`GET /api/documents/page`, driven by the `page` URL param), because it also filters by date range and status server-side — `ListPagination` renders the same way from `pageInfo`, just without a client `resetKey`. Pass a `resetKey` built from everything that changes a client-paged list (type tab, search, status filter) so it returns to page 1; the component hides itself when everything fits on one page. In RTL "قبلی" points right and "بعدی" left. The price list is deliberately not paged: its keyboard grid moves across all rows. Both the customers table (`components/customers/CustomerDataTable.tsx`, tanstack table v8) and the documents table (`pages/documents/DocumentListPage.tsx`) share the same card-with-toolbar look — a header row with the row count and a "نمایش ستون‌ها" column-visibility dropdown — but only the customers table pulls in tanstack: the documents table's columns are hidden with plain `useState`, since its rows are already server-paginated and don't need tanstack's row model.

**Row menus**: table row actions live in a `⋯` `DropdownMenu` (products, customers, documents). Use `modal={false}` so a sheet or alert dialog opened from an item doesn't leave `pointer-events: none` on the body, and stop click propagation on the cell: React events from the portal still bubble to a clickable row.

**Frontend** (`frontend/src/`): react-router routes are `/` (dashboard: headline cards, sales over the last 30 days as daily bars, and `RecentDocuments`, all fed by one documents request and one products request made in `DashboardPage`; its "new" button offers the first document type the role can write), `/products` (editable price list), `/customers`, `/users`, `/site` (public landing page), and `/documents/:typeSlug[/new|/:id]`. `/documents` redirects to `/documents/proforma`: the sidebar has a single "اسناد" entry, and the list page shows the three types as link tabs (`DocumentTypeTabs`) with search, a status filter, PDF download and draft deletion per row. `?customer=<id>` on a new-document URL pre-fills the buyer (used by the customers page menu); on the list page it filters to that customer (removable chip, carried across the type tabs and into "new"). The form tracks unsaved edits by comparing the serialized save payload with the last saved one: "صدور سند" saves pending edits before issuing, and `beforeunload` warns on close. A 409 `Already converted` from `/convert` carries `existing` in `ApiError.body`, and the form opens that document. The URL slugs (`proforma`, `invoice`, `goods-issue`) map to the API enum (`PROFORMA`, `INVOICE`, `GOODS_ISSUE`) in `lib/documentTypeSlug.ts`. One list page and one form page serve all three types. `App.tsx` keys the form by `typeSlug/id`, so state never carries over between documents. `DocumentFormPage` has an editor (`ItemsEditor`, `ProductPicker`, `PartyForm`) next to a live `DocumentPrint` preview. The type decides which columns and fields appear: invoices have discount and tax columns, goods-issue has vehicle and delivery fields. All HTTP calls go through `lib/api.ts`. Shared types live in `types.ts`. `@/` resolves to `src/`.

**PDF export**: `lib/exportPdf.ts` uses **html2canvas-pro** to capture a mounted `DocumentPrint` DOM node, then tiles the image across A4 pages with jsPDF. It embeds a **JPEG** (quality 0.82) with `compress: true` and one image alias reused on every page; the old PNG path stored raw pixels and made a single page about 10 MB (now tens of KB). `ExportPdfButton` (form page) exports the live preview by element id; `components/documents/useDocumentPdfExport.tsx` exports from the document list without opening the form by mounting the sheet for a moment behind the app (`z-index:-1` — `visibility:hidden` or `opacity:0` would capture a blank page). Capturing the rendered DOM is what keeps Persian text shaping and RTL layout correct. Don't switch to drawing text with jsPDF directly. Don't go back to plain `html2canvas`: it throws on Tailwind v4's `oklch()` colors. The `DocumentPrint` sheet must keep its fixed `w-[794px]` (no `max-w-full`), or the PDF layout shrinks with the screen width. On screen, `PrintPreview` shrinks it to fit with CSS `zoom` (so the preview never scrolls). `ExportPdfButton`'s `onclone` resets that zoom (`[data-print-zoom]`) so the PDF is always captured at full size.

**Persian formatting**: `lib/format.ts` has the Persian-digit conversion, Toman/Rial formatting, and a built-in Gregorian→Jalali date converter (no date library). `lib/numberToWords.ts` writes amounts out in Persian words for the printed totals. RTL overrides are in `rtl.css`.

The seed (`backend/prisma/seed.ts`) contains the company's full price list (in Toman) and three sample documents. It's idempotent: products are upserted by `code`, and the company row uses the fixed id `royahouse-main`. New documents link to the first company row.
